# Estado de seguridad (actualización coordinada)
Implementado en código: sesión revocable de servidor (8 horas), cookie HttpOnly/SameSite=Lax, CORS restringido a localhost:8443, CSRF, roles verificados en cada petición, contraseñas PBKDF2-HMAC-SHA256 con salt y 600.000 iteraciones, logout real y CLIENT_IDENTIFIER para bitácora. La actualización requiere ejecutar Actualizacion_PL_SQL.sql mediante aplicar_sql.py y restablecer las contraseñas antiguas. La edición de usuarios sin contraseña conserva el hash mediante NVL existente en SQL.

- Uso académico local: HTTP en loopback, un proceso Flask. Para producción se requieren HTTPS, cookie Secure, servidor WSGI, almacenamiento de sesiones compartido, limitación de intentos, cuenta Oracle de mínimos privilegios y revisión de seguridad adicional.
- Los 45 PA de escritura conservan COMMIT y ahora ejecutan ROLLBACK ante excepciones. Las consultas y funciones no controlan transacciones ajenas. Los triggers siguen ejecutándose dentro de la transacción del PA. Los errores de FETCH diferido se capturan también en Flask.
- La compra muestra cantidades calculadas por Oracle. La diferencia en Retorno muestra el valor persistido y se actualiza al guardar. El retorno de varios ítems continúa siendo una serie de transacciones independientes; ahora se informa cuántas se confirmaron si se interrumpe. Una respuesta de red perdida puede dejar el último resultado incierto; consultar Oracle antes de repetir.
